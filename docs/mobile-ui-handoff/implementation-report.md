## 与指南的适配差异

1. **未来开销说明**：指南写成周期日常剩余优先，但实际业务是缓冲金、储备金、日常可用余额依次补足。文字跟随现有业务，算法不变。
2. **余额校准说明**：现有可校准余额包含日常可消费余额、缓冲金、固定预留，排除储备金。保留原口径，没有改成仅 `spendable`。
3. **大额支出资金流向**：`advance` 实际可扣整个周期日常资金池，详情以存储的 `spendable` 快照展示，不能一律使用后续周统计余额。无法对应单一等式的旧记录会标注「记录后」，不伪造等式。
4. **本周超支**：原计算将本周剩余限制为0。界面保留此数值，使用原已花与额度展示超支金额和危险色。
5. **对比度**：亮色玉绿从 `#2F7D68` 微调为 `#296F5D`，按钮高光为 `#347D67`；赤铜为 `#9B511F`、高光 `#A85A24`；正向金额为 `#296E3F`。其余暖底与圆角方向保持一致。
6. **响应式导航**：统一使用悬浮双入口，桌面继续可达两个模块，不再依赖旧侧栏悬停展开。
7. **表单保存**：最低储备线覆盖改为与其他设置一起保存，关闭未保存输入会确认；设置编辑不会提前写入账本。

## 重跑方式

先运行 `npm run dev`，再运行三个检查命令。UI 检查需要 Playwright，可使用已安装版本，通过环境变量 `PLAYWRIGHT_MODULE` 指向包目录，`BROWSER_EXECUTABLE` 指向本机 Chromium/Edge。脚本使用独立浏览器、固定时间与虚构账目，仅在测试上下文里写 localStorage。

测试证据和截图位于 `.trellis/tasks/archive/2026-10/10-14-warm-touch-mobile-ui/research/qa/`。测试脚本要求 Vite 开发服务器提供 TypeScript 模块，不针对静态 preview 服务器运行。
