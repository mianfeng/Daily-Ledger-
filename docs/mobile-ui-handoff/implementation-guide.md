## 1. 目标与风格

个人本地账本，两个独立模块：**生活预算**与**铜钱生意**。手机上最常见的任务是：看本周还能花多少、快速记一笔；生意模块是记销售/进货、看现金与库存。

视觉方向「温润触控」：暖米灰底、奶白卡片、暖玉绿（生活）与赤铜（生意）两个强调色；圆润数字；元素有"凸起 / 凹陷"的物理质感，圆角大、按钮像可按压的按键。**两个模块靠强调色区分**，让用户一眼知道自己在哪个资金池。

## 2. 硬约束（不得破坏）

- **不修改业务计算**：`lib/daily.ts`、`lib/copper.ts` 的算法、扣款规则、分配规则、结转规则、快照逻辑、确认/取消/回滚逻辑一律不动。UI 展示用已记录的 allocation 和快照，不重新发明规则。
- **两个模块资金池互相独立**，不合并，不互相引用数字。
- **不新增**：登录、云同步、银行连接、多人协作、投资功能，以及任何未要求的新业务。
- **不改数据模型与存储**：localStorage 的键、结构、版本、导入导出文件格式保持不变。旧数据必须能正常打开。
- 保留的功能：生活预算全部功能（初始设置、收入分配、记支出含未来开销、余额校准、固定支出、周期详情、历史流水/资金流向、设置）；铜钱全部功能（销售/进货、待确认、确认/取消、已取消显示/隐藏、历史锁定、利润比例、库存成本补录、盘点、趋势、月度汇总）；整站 JSON 备份/恢复；两个模块各自的 Excel 导入/导出；日间/夜间主题。
- 不重新引入"储蓄比例/缓冲比例"作为主要收入分配的主表单（历史兼容字段只存储，不做主要输入）。
- 不假定预算周是自然周、周期是自然月；预计发薪日规则（每月15日，遇周末提前）只读展示。
- 不引入需要联网下载的字体；沿用现有 Noto Sans SC 的加载方式。
- 不放真实账目到测试夹具、截图或代码里。

### 字号

| 用途 | 规格 |
| --- | --- |
| 主数字（本周剩余） | 数字字体 46 / 1.1，700 |
| 次数字（周期日常剩余、缓冲金等） | 数字字体 19–26，700 |
| 页面/弹层标题 | 20–22，700 |
| 正文 | 15 / 1.5 |
| 辅助信息 | **最小 12 / 1.4**（现有 9–11px 全部提到 12px） |
| 金额 | 一律 `tabular-nums`，带明确正负号：`−¥38.00`、`+¥3,200.00` |

### 质感规则

- **凸起**（卡片、可点按钮、事件行容器）：`box-shadow: var(--raise)`。
- **凹陷**（进度槽、周柱轨道、开关槽、"原余额 − 变化 = 新余额"计算条、分段控件、类别按钮的选中态）：`box-shadow: var(--sunken)`。选中项用"压下去"表达，**不能只靠颜色区分选中**。
- **主按键**（记一笔、记录支出、确认）：`linear-gradient(180deg, var(--accent-hi), var(--accent))` + `inset 0 1px 0 #ffffff66, inset 0 -3px 0 #00000026, 0 8px 16px -6px var(--accent)`，底边 3px 的厚度要保留。
- **按压反馈**：`:active` 时 `translateY(1px)`，外阴影收紧，90ms。
- 亮色不加描边，层次靠阴影；暗色同理。

## 4. 版式与导航

- 手机基准 390px，同时验证 360 与 430；页边距 16px。
- **底部 Tab**：两个入口（生活预算 ｜ 铜钱生意），悬浮圆角条：左右外边距 14px，底部外边距 `18px + env(safe-area-inset-bottom)`，圆角 34px，`--raise`；当前项用 `--accent-soft` 托底并改用 `--accent` 文字/图标。默认进入生活预算。两个模块都必须在任意主页面可达。
- 页面内容底部要给悬浮 Tab 留出空间，避免末尾内容被遮挡。
- **弹层**（底部弹层）：顶部留约 56px 露出遮罩，圆角 36px，顶部有拖拽条（装饰）；内部滚动；主按钮固定在底部，**键盘弹起时随 `visualViewport` 上移，始终可点**。
- **子页**（全屏，左上返回）：周期详情、历史流水、预算设置、铜钱配置、月度汇总。资金流向详情可叠在历史流水上，**返回后回到原滚动位置**。
- 遮罩点击与 Escape 关闭；有未保存输入时关闭要二次确认。弹层打开时焦点移入、关闭时恢复；Tab 循环限制在弹层内。

### 导航关系

```

│   ├─ 记支出（弹层）

│   ├─ 周期详情（子页）：点周期 pill、每周预算柱图、提前支付 pill 进入
│   ├─ 历史流水（子页）：最近事件的「查看全部」
│   │    └─ 资金流向详情（叠加子页）

└─ 铜钱生意首页
    ├─ 记销售 / 记进货（弹层）
    ├─ 月度汇总（子页；手机上表格改为卡片列表）
    ├─ 铜钱配置（子页）：利润比例、库存调整（成本补录、盘点）、Excel
    └─ 确认 / 取消待确认销售（确认弹窗）
```

## 5. 页面级改动

对应 `design-brief.md` 的顺序。以下"设计稿"指上面链接里的画板。

### 5.1 生活预算首页（设计稿：Main）

纵向顺序：

1. **标题栏**：日期小字 + "生活预算"（22px 700）+ 右侧设置按钮（44px，凸起）。
2. **首次使用提示**（条件显示）：卡片，保留"先建立生活预算，旧流水保留"含义；首次进入仍自动打开初始设置。
3. **本周主卡**（首张卡，带 `--accent-soft → --card` 的淡渐变）：
   - 小标题"本周剩余 · 起止日期"；最大数字 = 本周剩余；
   - 凹陷进度槽（12px 高）显示本周消耗，下方一行：本周已用、本周额度；
   - 分隔线下两栏：**周期日常剩余**、**缓冲金**；
   - 两个 pill（高 ≥44px）：`周期 起–止 ›` 进入周期详情；`提前支付 ¥xx ›`（仅有提前支付时显示，警示色）进入周期详情的提前支付清单。
   - 无周期时：主卡改为空状态，说明"收入分配后开启第一个预算周期"，主按钮指向收入分配。
   - 本周超支时：主数字变 `--neg`，并加文案"本周超支 ¥xx"。
4. **快速记录 + 摘要**：左 128px 宽主按键"记一笔"（高约 104px，居中加号 + 文字）；右侧摘要卡**可点击或横滑**在"待处理""固定预留"之间切换，底部分页点。
   - 待处理：未付固定支出数量、校准提示、储备缺口；
   - 固定预留：金额、本期固定项数、待确认数。
5. **次级操作三键**：收入分配 / 余额校准 / 固定支出（等分，高 48px，凸起）。
6. **每周预算消耗**：卡片；每周一列，凹陷轨道里填充消耗；**区分过去 / 当前 / 未来周**；未来周的提前支付用斜纹填充（警示色）并在下方写金额；每列下方标签 + 剩余；点击进入周期详情；无周期时显示说明。
7. **最近关键事件**：卡片内的事件行（高 ≥64px）：备注、日期/创建时间、类型标签、金额、"提前支付"等标记（提前支付行显示"付款日期 → 归属日期"）；点击行体进入资金流向；删除动作单独一个按钮（≥44px，**与行点击区分开**，保留回滚确认）；"查看全部"进入历史流水。
8. **备份与旧数据折叠区**：并入预算设置子页，首页不再占位；导出生活预算 Excel、导入旧备份 Excel 的功能与文案保留。

> 本周剩余必须保持"本周剩余"含义，**不得**改名为总余额。

### 5.2 记支出（设计稿：Expense）

- 弹层；顶部标题"记支出"+ 关闭。
- **金额区**：大号数字输入（52px），前缀 ¥，光标条用强调色；数字键盘 `inputmode="decimal"`。
- **类别**：横向换行的按键组：日常、外食、其他、计划外、大额（选中为凹陷+强调色）。固定支出与未记录支出**不是**这里的类别。
- **日期**：普通状态显示"日期"，开启未来开销后改为"付款日期"。
- **备注**（可选）。
- **未来开销开关**：带说明"先付款，归属到未来预算周"。开启后：
  - 增加"归属日期"字段；
  - 出现警示提示条："付款立即从周期日常剩余扣款，计入归属日期所在预算周，不占用本周额度。归属日期须晚于付款日期，且不在付款所在预算周。"
  - 校验沿用现有逻辑，错误**内联**显示在字段下，不再 `alert`。
- 普通状态下显示扣款提示条："从周期日常剩余扣款，本周剩余 `旧值 → 新值`"（数值由现有计算接口给出）。
- **较大金额**：沿用"是否按大额处理"询问，改为确认弹窗（见 5.9）；**资金不足**需要确认继续时同样用确认弹窗。
- 底部主按键"记录支出"固定；键盘弹起不遮挡。

### 5.3 资金流向详情（设计稿：Flow）

- 子页，左上返回；摘要卡：类型标签 + 备注 + 金额（大号，支出用 `--neg`）+ 日期与创建时间。
- **资金来源 · 真实分配**：每个被扣口袋一行：口袋名 + 分配金额，下方凹陷计算条 **「原余额 ± 本笔变化 = 新余额」**（数值来自记录的快照，**不得用现在的余额推算历史**）。
- **资金缺口**：虚线警示框，文案"未被任何口袋覆盖，不显示被扣款的口袋"；**不能伪造一个被扣款的口袋**。
- 底部校验行：各分配 + 缺口 = 记录金额。
- **旧记录缺快照的降级**：
  - 有 allocation 但缺任一快照：只显示口袋与金额，**隐藏整个计算条**，改显警示提示："这条旧记录缺少前后余额快照，因此不显示『原余额 ± 变化 = 新余额』，也不会用现在的余额反推历史。"并带"旧记录"标签；
  - 缺 allocation：显示记录本身可用的内容，不显示来源区。
- **系统结转**：显示为内部转账，不按收入/支出着色；不显示删除。
- 底部"删除这笔记录（回滚各口袋）"：危险描边按钮，与详情点击区分，沿用回滚确认含义，走确认弹窗。

### 5.4 铜钱生意首页（设计稿：Business）

整个模块根容器加 `module-business`，强调色换为赤铜。

1. **标题栏**：小字"本地保存于此浏览器" + "铜钱生意" + 配置按钮。
2. **历史锁定提示**（条件显示）：提示条，沿用"旧版记录缺少精确资金明细，保留展示但不能删除"含义。
3. **资产摘要卡**：总资产（大数字）；下方两栏：现金合计、库存成本。总资产 = 现金合计 + 库存成本；库存按**成本**，不是零售价。手机上不再纵向堆三张卡。
4. **两个现金库**：两张并排卡：流动库（含利润比例）、存储库（含利润比例）。现金合计 = 流动库 + 存储库。
5. **记账入口**：两个主按键"记销售 / 记进货"，点击各打开弹层（内联表单搬进弹层，字段与规则不变：日期、金额、备注；销售另有成本、待确认开关；进货规则不变）。
6. **经营趋势**（有数据时）：卡片；"收利 / 库存"分段控件（凹陷槽）；近30天收入柱 + 毛利均线，或库存成本曲线；最高毛利日一行文字。图表必须有 `aria-label` 摘要；触摸时显示当日数值，不依赖 hover。
7. **月度汇总**：手机上由横向滚动表格改为**月份卡片列表**（每月：收入、成本、毛利润、待确认笔数/金额、进货、现金变化）；进入子页查看全部。
8. **最近流水**：行内显示备注、日期、类型、金额；销售行加"成本 / 利润"；利润为负时用 `--neg` 和明确的负号；
   - **待确认销售**：行内显示"待确认 · n 天后自动确认 · 款与库存已入账"，并给"确认"（主）与"取消并回滚"（危险描边）两个按钮（≥44px），点击进确认弹窗；
   - **已取消**：弱化、划线，不计入图表；"显示/隐藏已取消"开关保留；
   - **历史锁定**：锁图标，隐藏或禁用删除；
   - 空列表显示"暂无记录"。

### 5.5 其余屏幕（设计稿里没有独立画面，用同一套组件拼）

按下列规则实现，**使用已有 token 和组件，不要另造风格**：

- **初始设置 / 预算设置**（子页）：分组卡片。初次专属字段（当前可消费余额、当前缓冲金、当前储备金）仅初次显示；常规字段（储备固定金额、缓冲固定金额、储备金目标、缓冲金上限、最低每周生活线、储备金最低线覆盖，可空）；只读项（预计发薪日规则、当前固定预留）用弱化样式；已初始化后显示储备金余额/目标/进度/最低线/缺口。提示"设置影响后续收入分配和提醒，已生成预算周不会自动重算"。底部区域：主题切换、**数据与备份**（见 5.8）。
- **收入分配**（弹层）：类型分段控件（主要收入 / 零散收入 / 退款报销；**不含**余额修正）；金额、日期、备注；主要收入提示条保留原文含义（每笔主要收入开启新周期；固定预留有缺口时先补足；已覆盖固定项目标则不重复预留）；主按键"确认分配"。
- **余额校准**（弹层）：只有"当前可消费余额"一个字段；顶部必须说明："校准的是日常可消费余额，不包含所有口袋的总资产；差异可能形成未记录支出/余额修正流水。"主按键"完成校准"。
- **固定支出**（弹层/子页）：顶部固定预留摘要 + 目标金额输入（留空或0表示不预留）；新增表单（名称、金额、每月到期日）；清单行：名称、金额、每月几日、"标记已付"、删除。"已付"状态与当前周期关联，**标记已付会记录实际支出**，按钮文案与确认文案要体现这一点；"手动增加预留"是口袋间移钱，不是增加资产，需要说明。状态：无固定项、待支付、已支付、预留不足。
- **周期详情**（子页）：顶部三级金额层级——**本周期日常剩余 / 缓冲金 / 固定预留**，合计为**可动用余额**；可动用余额 + **储备金** = **总金额**；储备金显示余额/目标/进度。这几个名称必须区分，**不得混用**。其后：本周提醒；当前周期（起止、状态、收入、日常预算、储备增长、提前支付）；可展开的预算周列表（每周日期、预算、已花/提前支付、剩余、状态）；提前支付清单（付款日期与归属日期）；最近周期历史；无周期有空状态。
- **历史流水**（子页）：事件行列表，初始 20 条，"加载更多"每次 20 条；类型覆盖收入、支出、系统结转，含提前支付与校准产生的记录。
- **铜钱配置**（子页）：利润比例（流动库%、存储库%，**总和必须为100**，内联校验）；**库存调整**分区（成本补录、盘点设置总额），与日常进货明显区分，并写明"这是库存调整，不是进货付款"；模块 Excel 导入/导出（导入覆盖铜钱模块数据，需确认）。

### 5.6 空状态与异常

- 未初始化、已初始化但无收入周期、无流水、无固定项、铜钱无数据：各给一句人话说明 + 下一步按钮，不要空白。
- 页面加载失败（错误边界）：沿用现有逻辑，只换样式。
- 输入错误：**内联**显示在字段下；删除/覆盖/清理：走确认弹窗。

### 5.7 事件行与标签（跨页复用）

- 标签统一为"小圆角底 + 文字"，不只靠颜色：外食等类别用强调浅底；提前支付、缺口、待确认用警示浅底；旧记录用警示浅底。
- 金额颜色：支出/亏损 `--neg`，收入/盈利 `--pos`，系统结转用 `--muted`；**符号不能省**。

### 5.8 数据与备份（放在设置子页，两个模块各自一份入口说明）

- 置顶一段"本地保存"说明：数据保存在当前浏览器，没有登录和云同步；换设备或清理浏览器前请先导出。
- 分区一"整站备份（JSON）"：导出整站 / 恢复整站。**恢复前确认弹窗必须列明覆盖范围：生活预算与铜钱生意两个模块当前全部数据都会被覆盖**；格式错误给出内联提示；成功后给 Toast。
- 分区二"模块 Excel"：各模块自己的导出/导入，文案标明"仅本模块；导入会覆盖本模块数据"，与整站 JSON 区分。

### 5.9 确认弹窗

居中卡片（圆角 28px，`--raise`），标题 + 一句后果说明 + 两个按钮（取消 / 主操作）；危险操作（删除、恢复覆盖、清理）主操作用危险描边。
建议封装一个 Promise 形式的 `confirm({title, body, danger})`，让原有 `confirm()` / `alert()` 调用点逐个替换，**调用点的业务判断不变**。需要覆盖：大额处理询问、资金不足继续、删除记录（含回滚说明）、删除固定支出、标记已付、确认/取消待确认销售、整站恢复、Excel 导入覆盖、存储清理。

## 7. 可访问性

- 所有图标按钮有 `aria-label`；开关用真实 `<button role="switch" aria-checked>` 或原生 checkbox；不要用 `div` 加点击。
- 状态不只靠颜色（选中=凹陷，标签=文字，负数=符号）。
- 正文与背景对比度 ≥4.5:1，12px 辅助文字同样要求。**请用脚本把每一对前景/背景（亮暗各一遍，含两个模块强调色上的 `--on-accent`）实际算出来**，不达标就微调 token，不要忽略。
- 触控目标 ≥44×44px；弹层焦点管理与 Escape 关闭；`prefers-reduced-motion` 下取消回弹动画；图表有文字摘要。
- 底部固定元素使用 `env(safe-area-inset-bottom)`；输入区用 `visualViewport` 避让键盘。
