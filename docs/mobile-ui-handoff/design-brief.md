# Daily Ledger 移动端 UI 设计交接

提取日期：2026-10-14。代码基线：`fe60032`。语言：简体中文。金额：人民币。

本文件描述现有产品的页面构成、信息含义和交互要求，供外部设计 AI 使用。它不是新视觉方案，也不要求复刻现有样式。配套 `ui-manifest.json` 提供结构化页面清单，`design-prompt.md` 可直接复制为设计指令。

## 1. 产品与设计任务

这是个人使用的本地账本 Web 应用，有两个独立模块：

- **生活预算**：把收入分成生活费、缓冲金、储备金和固定支出预留，按预算周期与预算周控制支出。
- **铜钱生意**：记录销售、销售成本、进货、库存成本及利润分账。

移动端最常见的任务是查看本周还能花多少、快速记录支出；生意模块常见任务是记录销售/进货、查看现金与库存。界面需要让金额层级清楚、记账操作方便、复杂分配结果易理解。

设计 AI 可以重新决定审美、布局、卡片、字体、色彩、图表、导航以及弹层形式；必须保留现有功能与金额含义。不得把两个模块的资金池合并。不得默认添加登录、云同步、银行连接、多人协作或投资功能，这些都没有实现。

## 3. 生活预算首页：现有纵向顺序

| 顺序 | 区块 | 信息与动作 |
| --- | --- | --- |
| 1 | 标题栏 | Life Budget、生活预算、设置入口 |
| 2 | 首次使用提示（条件显示） | 先建立生活预算，旧流水保留；首次进入自动打开初始设置 |
| 3 | 本预算周主卡 | 本周剩余（最大数字）、起止日期、周期余额、本周已用、消耗进度、本周额度、周期状态、缓冲金；点击周期状态进入周期详情；有提前支付时显示金额并可进入详情 |
| 4 | 快速记录 + 摘要 | 左侧「记一笔」打开支出；右侧在「待处理」「固定预留」之间点击或横滑切换。待处理展示未付固定支出数量、校准提示、储备缺口；固定预留展示金额、本期固定项数、待确认数 |
| 5 | 次级操作 | 收入分配、余额校准、固定支出 |
| 6 | 每周预算消耗 | 每周已花/未花堆叠柱及预算、花费、剩余；区分过去、当前、未来周；未来周显示提前支付；点击进入周期详情；无周期时显示说明 |
| 7 | 最近关键事件 | 备注、日期/创建时间、类型、金额、提前支付等标记；点击查看资金流向；删除动作；查看全部打开历史流水 |
| 8 | 备份与旧数据折叠区 | 导出生活预算 Excel、导入旧备份 Excel |

以上顺序为代码现状，可以重排。应让用户首屏能理解本周可花金额，并很快找到记支出入口。储备金完整概览当前放在设置与周期详情，不单独占据首页主卡。

## 4. 生活预算弹层/子视图

现状统一使用底部弹层：遮罩、标题图标、关闭按钮、内部滚动。资金流向详情可以叠在历史流水上，关闭详情后应回到原上下文。设计可改为全屏子页，但要给出返回关系。

### 初始设置 / 预算设置

- 初次专属字段：当前可消费余额、当前缓冲金、当前储备金。
- 常规字段：储备固定金额、缓冲固定金额、储备金目标、缓冲金上限、最低每周生活线、储备金最低线覆盖（可空，自动计算）。
- 只读：预计发薪日「每月15日，遇周末提前」、当前固定预留。
- 已初始化后：储备金余额/目标、目标进度、最低线、缺口。
- 操作：保存设置；主题切换、导出整站、恢复整站。
- 提示：设置影响后续收入分配和提醒，已生成预算周不会自动重算。

### 收入分配

- 类型：主要收入、零散收入、退款报销。余额修正是系统/校准流水类型，不是这里的第四个手动选项。
- 字段：金额、日期、备注。
- 主要收入提示：每一笔主要收入都开启新周期；有固定预留缺口时先补足；已覆盖固定项目标则不重复预留。
- 操作：确认分配。

### 记支出

- 可选类别：日常、外食、其他、计划外、大额。
- 字段：金额、日期、可选备注。
- 开关：未来开销；开启后日期显示为付款日期，增加归属日期。
- 未来开销：付款立即扣款，统计归属未来预算周；归属日期须晚于付款日期，不能仍落在付款预算周。
- 较大金额：提示并询问是否按大额处理；资金不足时可能需要确认继续记录。
- 操作：记录支出。固定支出和未记录支出属于流水类别，但不是本表单的普通类别按钮。

### 余额校准

- 字段：当前可消费余额。
- 操作：完成校准。
- 必须让用户理解校准的是日常可消费余额，不是包含所有口袋的总资产；差异可能形成未记录支出/余额修正流水。

### 固定支出

- 摘要：固定预留金额；可以输入目标金额并保存，留空或0表示不预留。
- 新增字段：名称、金额、每月到期日；操作：添加固定支出。
- 清单行：名称、金额、每月几日、标记已付/已支付、删除。
- 已付状态与当前周期关联；标记已付会记录实际支出，不是单纯的视觉勾选。
- 主要收入优先补固定预留缺口；手动增加预留是口袋间移钱，不是增加资产。

### 周期详情

- 总金额、可动用余额、储备金余额/目标/进度。
- 分解：本周期日常剩余、缓冲金、固定预留。
- 本周提醒：日期、剩余、预算、已花、进度。
- 当前周期：起止日期、状态、主要收入+其他收入、日常预算、储备增长、提前支付。
- 可展开预算周列表：每周日期、预算、已花/提前支付、剩余与状态。
- 提前支付清单：付款日期与归属日期。
- 最近周期历史摘要；无周期时要有空状态。

### 历史流水 / 资金流向

- 历史流水按日期/创建顺序展示，初始20条，每次加载更多20条。
- 类型覆盖收入、支出、系统结转，包含提前支付与校准产生的记录。
- 详情展示：记录类型、备注、金额、日期/创建时间、资金来源或去向、真实分配金额，以及有数据时的「原余额 ± 本笔变化 = 新余额」计算过程。
- 覆盖不了的支出差额显示为资金缺口，不能伪造一个被扣款的口袋。
- 旧记录可能缺少 allocation 或前后余额快照，应显示可用内容；缺少任一快照时不显示计算过程，不能按现在的余额推算历史。
- 系统结转是内部转账，不算收入或支出；删除动作应与详情点击区分，并保留回滚确认含义。

## 5. 铜钱生意首页：现有纵向顺序

| 顺序 | 区块 | 信息与动作 |
| --- | --- | --- |
| 1 | 全局本地账本栏 | 本地存储说明、日间/夜间、整站导出/恢复 |
| 2 | 标题栏 | Copper Business、铜钱生意、配置入口 |
| 3 | 历史锁定提示（条件显示） | 旧版记录缺少精确资金明细，保留展示但不能删除 |
| 4 | 资产摘要 | 总资产、现金合计、库存成本；手机当前纵向堆叠 |
| 5 | 两个现金库 | 流动库余额及利润比例、存储库余额及利润比例 |
| 6 | 记账表单 | 收/进货切换、日期、金额、备注；销售额外有成本和待确认开关；提交按钮 |
| 7 | 经营趋势（有数据） | 收利/库存切换；近30天收入、毛利、库存变化；收入柱+利润均线，或库存成本曲线；最高毛利日 |
| 8 | 月度经营汇总（有数据） | 月份、收入、成本、毛利润、待确认笔数/金额、进货、现金变化；当前横向滚动表格 |
| 9 | 最近流水 | 备注、日期、类型、金额；销售成本/利润；待确认到期信息；取消和历史锁定标记；显示/隐藏已取消 |

销售待确认行提供确认、取消；普通记录提供删除；历史锁定不可删除。空列表显示「暂无记录」。可以把现有首页内联记账表单重设计成独立底部弹层，但字段和业务含义应完整。

### 铜钱设置

- 利润比例：流动库%、存储库%，总和必须为100；保存比例。
- 库存成本补录：本笔成本、备注；补录库存。
- 盘点设置总额：库存成本总额、备注；记录调整。
- 模块 Excel 导出/导入（导入覆盖铜钱模块数据）。
- 补录与盘点是库存调整，不是进货付款，应与日常进货表单区分。

## 6. 必须保持的业务语义

### 生活预算金额

- 本周剩余是当前预算周还能花的金额，不能改名为总余额。
- 本周期日常剩余 = `pockets.spendable`。
- 可动用余额 = 本周期日常剩余 + 缓冲金 + 固定预留。
- 周期详情总金额 = 可动用余额 + 储备金。
- 预算周由收入周期生成，不应假定是自然周一到周日，也不应假定周期等于自然月。
- 每笔主要收入开启新周期，包括旧周期尚未结束时；预计发薪按每月15日、周末提前到工作日规划。
- 周结余按60%缓冲/40%储备结转，受缓冲上限约束；周期结转将现有缓冲40%移入储备、60%留在缓冲。
- 普通支出、固定支出、大额支出、提前支付使用不同资金来源；界面应使用已记录的 allocation 展示，不重新发明扣款规则。
- 设置中兼容存储的历史百分比字段不是当前主要收入分配的主要输入，不能重新设计成「储蓄比例/缓冲比例」主表单。

### 铜钱金额与状态

- 现金合计 = 流动库 + 存储库；总资产 = 现金合计 + 库存成本。库存按成本，不是零售价。
- 毛利润 = 销售金额 - 销售成本；销售成本回到流动库，正利润按两库比例分配；非正利润时销售款进入流动库。
- 进货减少现金并增加库存成本；销售减少库存成本。销售成本不能超过现有库存成本；现金不足不能进货。
- 待确认销售创建时已影响现金和库存；手动确认/到期自动确认只改状态，不能再次入账。
- 待确认销售10个自然日后在应用处理时自动确认，不代表后台定时服务。
- 取消待确认销售回滚资金/库存，保留取消记录，并从统计图表排除；删除已取消记录不能再次回滚。
- 利润可以为负，设计必须处理负数；历史锁定记录不能删除。

## 7. 设计覆盖状态清单

| 类别 | 需要覆盖 |
| --- | --- |
| 首次使用 | 未初始化、初始设置、初始化后尚无收入周期 |
| 正常预算 | 有周期、当前周、未来周、过去周、无流水 |
| 预算变化 | 延长期、本周超支、缓冲较低、储备缺口、资金不足、提前支付 |
| 流水详情 | 收入分配、多口袋支出、系统结转、缺口、旧记录缺快照 |
| 固定项 | 无固定项、待支付、已支付、预留不足 |
| 生意 | 无数据、正常销售、亏损销售、待确认、已确认、已取消、历史锁定 |
| 表单 | 输入中、错误、确认、完成；键盘弹出后主按钮仍可用 |
| 备份 | 导出、导入确认、格式错误、恢复成功 |
| 主题 | 同一页面亮色/暗色、图表和弹层可读性 |

## 8. 交付建议（给设计 AI）

先交付四个关键高保真移动视图：生活预算首页、记支出、资金流向详情、铜钱生意首页。随后用组件/状态清单补齐收入、设置、固定支出、周期详情、历史流水、铜钱设置和确认状态。不要把“四个主视图”理解为可以删除其余功能。

- 手机基准建议390px宽，同时检查360px与430px；这是新设计验证目标，不是当前代码断点。
- 金额使用真实可读的数字与明确的正负号；大金额、长备注、多周周期均应容纳。
- 说明点击热区、底部安全区、键盘避让、图表触摸、弹层滚动及返回关系。
- 请输出具体色值、中文字体与数字字体、字号层级、间距、圆角、边框、图标和动效规则。
- 当前组件有不少9–11px文字和密集表格；可优先改善信息密度与阅读性，不应仅换色。
- 示例数字可以自拟，但必须算得通，并标为演示数据；不得声称是用户真实账目。
