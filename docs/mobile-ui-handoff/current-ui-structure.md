# Daily Ledger 当前 UI 结构

提取日期：2026-10-16。代码基线：`bf84e20`（main）。依据当前源码静态提取，本次未重新运行浏览器视觉检查。

这是**改版后的实际结构**，不是下一轮设计建议。配套 `current-ui-manifest.json` 是同一结构的机器可读版本。旧 `design-brief.md` 和 `ui-manifest.json` 描述改版前版本，不能当作当前页面结构。

## 1. 页面与导航树

```text
App
└─ AppErrorBoundary
   └─ UiProvider（主题、模块强调色、确认弹窗、Toast）
      └─ app-shell
         └─ LedgerApp（两个账本的数据与整站备份）
            ├─ app-main
            │  ├─ DailyLedger：生活预算（默认）
            │  │  ├─ 初始设置 / 预算设置 → 全屏覆盖页
            │  │  ├─ 收入分配 → 底部弹层
            │  │  ├─ 记支出 → 底部弹层
            │  │  ├─ 余额校准 → 底部弹层
            │  │  ├─ 固定支出 → 底部弹层
            │  │  ├─ 周期详情 → 全屏覆盖页
            │  │  ├─ 历史流水 → 全屏覆盖页
            │  │  │  └─ 资金流向 → 叠加的全屏覆盖页
            │  │  └─ 最近事件 → 可直接打开资金流向
            │  └─ CopperShop：铜钱生意
            │     ├─ 铜钱配置 → 全屏覆盖页
            │     ├─ 记销售 → 底部弹层
            │     ├─ 记进货 → 底部弹层（与销售共用表单模板）
            │     └─ 月度经营汇总 → 全屏覆盖页
            └─ app-tabs：生活预算 / 铜钱生意

document.body（React Portal，实际 DOM 不在 app-shell 内）
├─ Overlay：底部弹层 / 全屏覆盖页
├─ Overlay(confirm)：居中确认弹窗，可叠在表单上
└─ Toast：操作完成反馈
```

页面由 React 本地状态切换，没有 URL 路由、独立页面地址或深链接。下文及 JSON 中的页面 ID 是交接标识，不是网址。切换模块时会卸载原模块组件，其表单、弹层等局部状态不属于永久保存的数据。

## 2. 全局外壳与布局

| 构成 | 当前实现 |
| --- | --- |

| 7 | 最近关键事件 | 最新3条；类别、备注、日期、金额，提前支付显示付款/归属日期；行体打开详情，独立删除按钮；查看全部进入历史流水 |

## 4. 生活预算的表单与详情

| 页面 ID / 标题 | 容器 | 内容、字段与动作 |
| --- | --- | --- |
| `daily.settings` 初始设置/预算设置 | 全屏覆盖页 | 初次输入当前可消费余额、缓冲金、储备金；常规输入储备固定金额、缓冲固定金额、储备目标、缓冲上限、最低周生活线、最低储备线覆盖；只读预计发薪规则、当前固定预留；已初始化展示储备概览；保存设置固定在底部；下方内容区有数据与备份 |
| `daily.income` 收入分配 | 底部弹层 | 主要收入/零散收入/退款报销分段控件；金额、日期、备注；主要收入开启新周期和补固定预留缺口说明；底部确认分配 |
| `daily.expense` 记支出 | 底部弹层 | 大号金额输入 → 日常/外食/其他/计划外/大额五类按键 → 日期、可选备注 → 未来开销开关 → 条件出现归属日期与扣款说明 → 大额提醒或普通扣款/本周剩余预览 → 底部记录支出 |
| `daily.calibration` 余额校准 | 底部弹层 | 口径说明、当前账面可消费余额、输入当前可消费余额、底部完成校准 |
| `daily.fixed` 固定支出 | 底部弹层 | 预留摘要、目标金额与保存；名称/金额/每月到期日与新增；已有清单的标记已付/已支付/删除；已付按钮禁用；无固定项空状态 |
| `daily.cycle` 周期详情 | 全屏覆盖页 | 总金额、可动用余额、储备余额/目标/进度；日常剩余/缓冲/固定预留；本周提醒；当前周期日期/状态/收入/预算/储备增长；可展开周列表；提前支付清单；最近周期历史 |
| `daily.history` 历史流水 | 全屏覆盖页 | 事件列表，初始20条、加载更多每次20条；收入/支出/系统结转；打开资金流向；非系统结转有独立删除按钮 |
| `daily.flow` 资金流向 | 叠加全屏覆盖页 | 摘要卡：类型/备注/金额/日期/创建时间；真实来源或去向；有完整快照时展示原余额±变化及新余额；未覆盖差额独立显示；非转账可删除并回滚 |

资金流向的实际降级规则：

- 有 allocation、缺任一前后快照：保留口袋和金额，整个计算条不显示，标注旧记录。
- 无 allocation：只展示原记录信息和缺失说明，不伪造资金来源。
- 单项分配与快照无法对成等式：新余额前写「记录后」，不写错误的等号。
- 系统结转标为内部转账，不按收入或支出处理，详情不提供删除按钮。

## 6. 共享组件与覆盖层行为

| 组件 | 责任 |
| --- | --- |
| `UiProvider` / `useUi` | Promise 确认、Toast，以及 Portal 的主题/模块样式类 |
| `Overlay` | sheet/page/confirm 三种外观；标题、返回或关闭、滚动内容；有 footer 时底部按钮独立于内容滚动 |
| `InlineError` | 激活表单中的行内错误，使用 `role=alert` |
| `BackupSection` | 本地保存说明 → 整站JSON及全局控件 → 本模块Excel；两个设置页共用 |
| `BottomSheet` | 生活预算的 Overlay 适配层；按标题决定 sheet/page；抽取主提交按钮到 footer |
| `SectionShell` | 生活预算区块表面 |
| `TransactionEventRow` | 生活事件行、详情点击区、独立删除区 |
| `TransactionFlowDetail` | 流向摘要、来源/去向、快照计算条、资金缺口、旧记录降级 |
| `NumberField` / `DateField` / `TextField` | 有标签的表单字段 |
| `SegmentedChoices` / `SubmitButton` | 收入类型切换与表单主提交 |

覆盖层经 Portal 挂到 body，单独携带当前主题与模块强调色。背景 root 会 inert、禁止背景滚动；最上层捕获 Escape、限制 Tab 焦点；关闭后恢复原焦点。内容页保留在下层，资金流向关闭后返回原历史上下文。

编辑型层具有未保存输入保护，关闭/返回/遮罩/Escape 会确认放弃。上传文件不视作未保存表单；只读详情不提示放弃。使用 `visualViewport` 的高度和偏移调整弹层，底部固定按钮不随内容滚动。拖拽条是装饰，没有拖拽关闭手势。这里的关闭不是浏览器历史路由返回。

## 8. 不应混淆的产品口径

- 本周剩余 ≠ 周期日常剩余 ≠ 可动用余额 ≠ 总金额。
- 可动用余额 = 日常剩余 + 缓冲金 + 固定预留；总金额再加储备金。
- 校准输入的账面口径包含日常资金、缓冲金、固定预留，排除储备金。
- 提前支付保留付款日期与归属日期；资金优先从缓冲、储备补足，而不是仅按归属周推迟付款。
- 库存以成本计价；生意总资产 = 两库现金 + 库存成本。
- 待确认销售已影响资金与库存；确认只改状态，取消才回滚。
- 整站JSON覆盖两个模块，本模块Excel仅作用于对应模块；无登录与云同步。
